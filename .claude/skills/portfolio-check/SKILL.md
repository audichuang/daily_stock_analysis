# 持倉檢視與記帳

**自主邊界**：查價、讀帳本、照券商截圖記帳、更新持股計畫記憶——直接做，不必先問（使用者 2026-10-21 授權）。下單永遠是使用者自己按。給建議要附數字與明確傾向，不要把決定丟回給使用者。

## 1. 先拉即時快照（每次談持股都先跑）

```bash
doppler run -p shioaji -c dev -- uv run python .claude/skills/portfolio-check/snapshot.py
```

- 台股「來源」欄要是 `SHIOAJI`。不是就代表金鑰沒注入，拿到的是延遲價（yfinance 約慢 20 分鐘）或昨收，報價時要標明。平台有永豐金鑰，別說「本機拿不到即時價」；NAS Web 的 `/api/v1/stocks/quotes` 是備援（要登入，位址見 ops repo 的 dsa manifest）。
- **持股數字的真源是帳本**（應用庫 `dsa` schema 的 portfolio 表，`PortfolioService`），各券商的庫存只能靠使用者貼的截圖記進來、核對。帳本按「券商×市場」分帳戶，記帳前用 `list_accounts()` 的 `broker`／`market` 對到正確帳戶——別從截圖風格或「有串永豐」就猜券商，使用者的台股不在永豐。
- 永豐 Shioaji 金鑰在這裡**只用來取報價**，不是帳務來源：它不提供複委託，帳戶查詢 `list_positions` 也回 406 Account Not Acceptable（`signed=False`，2026-10-21 實測）。`STOCK_LIST` 是每日報告的分析清單，不等於持股。
- **基金不在帳本**（帳本只收股票代碼、沒有基金淨值來源）：基金的現值、報酬率、淨值日記在持股記憶裡，使用者貼新截圖才更新。算整體權重時要把基金加回去，快照最後的「全部帳戶合併」不含基金。

## 2. 對照計畫與結構

- 持股計畫、集團關係、重複曝險存在 agent 個人記憶（`holdings-plan`、`portfolio-structure`），不進版控；具體數字一律以步驟 1 為準，不從記憶抄。
- 權重要按**集團合併**算（母子公司、追蹤同一指數的槓桿 ETF），並以**全部帳戶＋基金**為分母——只看單一帳戶會把集中度算錯（同一檔可能分在兩家券商）。
- 記進帳本的股票會自動進每日報告（`.env` 的 `ANALYZE_PORTFOLIO_HOLDINGS=true` 由 `main.py::_merge_portfolio_holdings` 併入），不必另加 `STOCK_LIST`——加了賣掉後會殘留。但每日報告只拿到代碼、不帶成本；要帶成本的持倉分析是 Web 持倉頁的分析按鈕。基金沒有每日分析，要建議時另做研究。

## 3. 引用系統建議時的坑

- 每日報告／Web 分析的「減倉」主要由均線排列決定（`src/stock_analyzer.py` 的 trend_strength＋prompt 評分區間），**不看持有成本與論題**；它說減倉只代表技術面不支持。
- **盤中**從 Web 觸發的分析可信度較低：沒走完的 K 棒已計入均線（可能把排列翻成強勢空頭），量比拿半日量比全日量會被判成縮量。重大決定看 18:00 收盤後的報告。

## 4. 記帳（使用者貼券商成交截圖時）

`PortfolioService().record_trade(account_id=<該券商帳戶>, symbol="6191.TW", trade_date=..., side="sell", quantity=..., price=..., trade_uid="<YYYYMMDD>-<委託書號>", note=...)`

- 買賣方向以截圖「種類」欄（現賣／現買）為準；使用者口頭說錯時照截圖記，並告訴對方。
- `trade_uid` 用日期＋委託書號：同一張截圖重貼會被擋下，不會重複記；只記新出現的那幾筆。
- 只有庫存截圖（沒有成交明細）時記成當日期初買進：成本＝損益÷報酬率（或市值÷(1+報酬率)），`trade_uid` 用 `open-<券商>-<代碼>`，note 寫明是反推。美股定期定額只給台幣現值時，股數與美元成本用當時匯率估算並在 note 標「待核對」。
- 手續費／證交稅沒有對帳單就填 0，所以帳本均價會比券商庫存略低；股數用券商庫存截圖核對，對不上就說出來。
- 記完重跑步驟 1，並更新持股計畫記憶的進度（日期、實際成交、剩餘股數）。
