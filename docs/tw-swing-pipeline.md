# 台股波段候选流水线（量化预筛 → AI 事件面研究 → 回验）

本文是这条流水线的**唯一契约文档**：四层各自负责什么、各自被验证到什么程度、哪些结论**不**成立。
逐次研究的过程记录留在本地 `.claude/reviews/`（已 gitignore），本文只写沉淀下来的结论；
每日决策日志在 `journal/`（进版控，见 `journal/README.md`）。交易成本与二代健保的边界见
[`tw-trading-costs.md`](tw-trading-costs.md)。

> 这条流水线的产出是**候选名单与判断记录**，不是投资建议。5 空位全期 Sharpe 为 1.19，低于
> 0050 的 1.23，且回撤 -45.7% 对 -34.0%；同窗口 3/5/10 空位为 0.95~1.04 对 1.15，走前为 0.73 对
> 1.15。现有证据不足以把它当自动交易讯号，且回撤最深达 0050 的 1.9 倍。

## 每天早上的固定流程（開盤前）

時間座標：台股 **09:00 開盤 / 13:30 收盤**；美股（夏令）台北時間 **21:30~04:00**；台指期夜盤到
**05:00**。所以**早上 06:00 之後**隔夜資訊已經全部到齊，07:00~08:30 是最合適的作業窗口。

```bash
make morning          # 一键：补资料 → 昨晚国际盘 → 待触发计划 → 今日候选
```

它依序做五件事，任何一件都不该跳过：

| 步骤 | 做什么 | 为什么不能省 |
| --- | --- | --- |
| ① `cli daily` | 补昨天的法人/融资/估值/大盘指数并刷新近期复权事件 | 避免只补最后一天或沿用旧复权因子 |
| ② `health --strict` | 对齐近期 price/TAIEX/法人/融资日期，并检查除权息复权事件 | 这五项缺日就停止，不把 missing 当 0；**`valuation` 与月营收不在门槛内**（见下） |
| ③ `overnight.py` | 道琼/标普/纳指/**费半**/**台积电 ADR**/油价/汇率，带日期戳 | DB 只到昨天 13:30，之后到开盘有约 20 小时盲区 |
| ④ `verify-decisions` | **已留档、未到期**的判断：现价 vs 进场区间、失效条件 | 待触发的计划靠人记得就一定会漏 |
| ⑤ `make screen` | 今日候选 | — |

之後由 agent 跑 skill `tw-swing-research` 做第 2 层，把每檔候選（含 `pass`）各自追加一行到
`journal/swing-decisions.jsonl`；候選為 0 時不捏造決策資料。只要有新增決策，就在当天 commit：

```bash
git add journal/ && git commit -m "journal: decisions for YYYY-MM-DD"
```

脚本抓不到、仍要人工查一项：**台指期夜盘 05:00 收盘** ÷ 前一交易日现货收盘 = 开盘预期缺口
（注意 17:00~21:30 的夜盘报价不含美股资讯）。

**為什麼②不能省**：DB 只到昨天 13:30，之後到開盤有約 20 小時盲區。踩過两次——一次拿旧决策日志
充当今天的答案，一次 0 档候选就跳过隔夜检查；两次结论都碰巧对，但推导过程是坏的。

**手上有持倉時**（尚未自動化，要人工做）：逐檔對照 `journal/` 裡那筆的 `invalidation`，看論題失效
條件有沒有觸發。現行契約是固定持有 60 個交易日，**流程裡沒有賣出決策點**，所以這一步目前靠人。

**不用每天跑的**：`make verify-decisions`（60 交易日後才有到期樣本，每月看一次即可）、
`make measure` / `make portfolio`（只在改過門檻、補過歷史資料、或要重新驗證結論時跑）。

## 四层与命令

| 层 | 做什么 | 入口 |
| --- | --- | --- |
| 1 量化预筛 | 全市场扫出每天 2~5 档候选，输出 markdown + JSON | `make screen`（`scripts/screen_tw.py`） |
| 2 事件面研究 | 逐档查催化剂、判 `enter`/`pass`，写决策日志 | skill `tw-swing-research`（建议用 sonnet 子代理执行） |
| 3 分布量测 | 量讯号的前瞻报酬分布（事件级，不做部位模拟） | `make measure`（`scripts/measure_signal_forward.py`） |
| 4 回验 | 60 交易日后算这一层有没有加值 | `make verify-decisions`（`scripts/verify_swing_decisions.py`） |

组合层验证（回答「有限资金拿不拿得到」）：`make portfolio`、`make portfolio-wf`
（`scripts/portfolio_walkforward.py`）。

数据全部来自本机 Postgres `market` schema（`DATABASE_URL` 在 `.env`），爬取见
`market_data/AGENTS.md`。**价格一律经 `market.price_adjustment` 前复权**——未还原价算报酬会让
上柜除息造成约 20pp/年偏差、0050 的 1:4 分割显示 -65.79%。

`make morning` 与 `make swing` 都在筛选前执行 strict health gate。检查失败时先修复资料，不能继续
产生看似正常的候选。`daily` 会连续补近期交易日；除权息抓取、推导与 `price_adjustment` 的近期
替换在同一 transaction 完成，失败不会留下半套因子。TAIEX 优先读取可指定日期的 TWSE FMTQIK
报表（OpenAPI 仅作 fallback）；法人／融资依 T+1 契约，从次新交易日起检查，不把当天尚未发布误报为缺日。
`health` 的近期视窗与 `daily` 的自动修复视窗共用 `crawl.RECENT_SESSIONS`——检查得比修复得远，
就会擋在一个「重跑 daily 也补不到」的缺口上。全历史 thin day 只报不擋（同理：daily 修不到）。

**门槛不涵盖 `valuation` 与月营收，而这不是疏漏、是发布时点问题**：`BWIBBU_ALL` 是无日期参数的
当日快照端点，实测 2026-07-30 18:00 仍回 07-29 的资料（列数 1,081 正常、日期是旧的），把它纳入
strict 会让盘后跑的 `make morning` 每天先红一次。代价是**当天 PE/PB/殖利率整栏为空**。

估值缺日曾让 `screen_tw` 的 `momentum` 排序整栏 NaN（`fillna(median())` 的 median 本身是 NaN
→ rank 全 NaN → 每一档 `score` 都是 NaN，而 `sort_values` 维持原顺序也就是代号序，于是
`--top N` 静默退化成「代号最小的 N 档」）。2026-07-30 实测（`valuation` 覆盖 0 檔、候选 37 檔）：
旧实作 **37 檔的 `score` 全为 NaN、顺序完全是代号升冪**；修正后 37 檔全部有效、顺序由其余四项
决定。注意 `--json` **不输出 `score` 栏位**，所以判断这件事要看排序而不是看 JSON。
**已修**：`_pe_score()` 在整栏缺值时回中性 0.5，保住其余四项（动能／筹码／当日／位阶）仍然有效
排序。这只影响 `momentum` 分支——`breakout` 的排序是 `yoy + 0.5×量比 + 0.5×d5`，没有 PE 项，
200 次乱序检定实作的也是 breakout 公式，所以那份检定不受影响。

## 第 1 层：冻结的讯号定义

```
日均额 ≥ 2 亿（20 日均）
排除 ETF（00xx）、TDR（91xx）、创新板（名称后缀 -创）
收盘 > 不含最近 5 天的 60 日高      # high.shift(5).rolling(61).max()
5 日涨幅 ≥ 5%
5 日／60 日量比 1.3 ~ 2.0          # 上限是同样本选模，见下方「站不住的部分」
月营收 YoY ≥ 20%                   # announce_date < 当日、且在 45 个**曆日**内
```

**live 与量测必须逐格相同**，否则量到的不是会下单的那组讯号。两个踩过的口径差：
`hi60_prior` 的视窗（实测 918 vs 894 事件、只有 859 重叠）、月营收保鲜期是 45 个**曆日**而不是
45 个**交易列**（约 63 曆日，会改变 44 个 signal cell 与一个事件）。现在两边共用同一套定义，
并有端到端验证：量测在 2026-07-24 发的讯号 = live 候选名单 `{2615, 6166}`。已发表的 prior 只随
`strategy_version`／`config_hash`／`cost_model_version` 建新版本，不在旧批次上事后改写。

排序（`score`）**只决定呈现顺序**，200 次乱序对照里没有观察到优势（见下），不要当进场理由。

## 第 3 层：讯号的前瞻报酬分布

讯号始于 2020-01，结果资料截至 2026-07-24（可到期讯号约截至 2026-04）。每笔以 20 万元名目
本金、实际股数与现金流计算：买卖两端券商手续费 0.1425%（每笔最低 20 元），卖出另收 0.3%
证交税，并对买／卖成交价各套用 0.15% 滑价；T+1 合法开盘买进，第 60 个交易日收盘卖出。
同一档相隔 >60 个交易日才算新事件
（3,951 笔名目讯号 → 排除 404 笔右端截断 → 3,547 笔可量测讯号 → 974 个事件）。

```
                       事件    均值    中位    勝率  賺賠比 两平勝率 P(≥30%) P(≤-20%) 最差
候选池                  974  +9.93% +0.83% 51.3%  2.20  31.2%  20.2%   14.8%  -54%
对等基准(同池、有月营收)7319  +4.67% -0.67% 48.5%  1.79  35.9%  12.0%   11.8%  -74%
全流动股基准           10255  +4.60% -1.29% 47.3%  1.81  35.5%  12.5%   13.4%  -74%
```

均值的 **full-calendar circular block bootstrap 95% 区间 +3.14% ~ +16.69%**（block=60 交易日，
2,000 次、seed=42）。IID 区间 +7.53%~+12.32% 是**假精度**——事件在时间上聚集，别引用。

方法上四个必要处理（每一个都是踩过之后补的）：

1. **宇宙用 `market.price` 判定，不用 `stock_info`**——后者只有现存约 1,100 档，用它过滤历史等于
   前视 + 存活偏误。**但组合层必须排除创新板**（live 的 `screen_tw.funnel` 就排除它）：不排除
   等于让组合买进 live 永远不会买的标的，而全库唯一过得了流动性门槛的 7610 是 10 倍股。
   旧版敏感度显示它单档可把 Sharpe 撑高约 0.2，足以改变风险调整报酬的定性解释。
2. **区分样本右端截断与真下市**：前者报酬未知一律 NaN 排除（旧版把 409 笔捏造成报酬，而样本
   末端的讯号往往落在同一波行情、会整批偏向同一方向），后者必须结算（`--delisting last|zero`）。
3. **事件级去重**，且是「与上一个**保留的事件**相隔 > h」而非与上一个名目讯号相隔 > h。
4. **区块 bootstrap 的母体是完整交易日历**，circular（绕回开头）才不会让样本两端被系统性少抽。

## 组合层：有限资金拿得到吗

100 万元起始本金、等权、固定持有 60 交易日，使用与事件层相同的逐笔现金流成本，**排除创新板**。
平盘来回约 0.882%（含单边 0.15% 滑价），但最低手续费会随部位大小改变。0050 基准唯一刻意不同
的是证交税：ETF 卖方 **0.1%**、个股 0.3%（沿用个股税率会高估基准成本，而结论正是「输给 0050」）。

「同窗口」一律指 **2021-04-29 起**，也就是 walk-forward 第 0 折训练结束、开始交易的那一天；
写死日期是因为「2021-04 起」这种模糊说法曾让全期与同窗口的数字被混在同一行引用。

```
                            年化    年化波动  Sharpe  最大回撤
组合（5 空位、全期）       +45.5%   37.4%    1.19   -45.7%
0050 买进持有（全期）      +28.4%   22.3%    1.23   -34.0%
同窗口 2021-04-29 起：3 空位 +43.3%／1.04／-65.1%　5 空位 +39.7%／1.04／-60.7%
                    10 空位 +30.5%／0.95／-52.5%　0050 +26.0%／1.15／-34.0%
走前选参（同窗口样本外）   +23.4%／0.73／-58.7%　0050 +26.0%／1.15／-34.0%
```

- **资金竞争没有杀掉优势**：3,939 笔名目讯号 → 进场 130 次（已平仓 125、期末仍持有 5），另有
  372 笔落在已持股。**两侧都事件去重**后（买到的一侧因持有 60 日天然去重，没买到的一侧每天
  重复追加）：买到的 125 笔均值 +12.78%、没买到的 908 个事件 +9.96% → 排挤成本 **-2.82pp**（全期）。
  同窗口 3/5/10 空位分别是 -6.19／-4.74／-2.56pp，walk-forward -0.15pp，全部 ≤0。
- **风险调整后输给 0050**：全期 5 空位 Sharpe 1.19 < 0050 的 1.23，且回撤更深；
  同窗口 3/5/10 空位 0.95~1.04 < 1.15，walk-forward 0.73 < 1.15。**没有一个设定赢过 0050**，
  且完全不随分散改善。多出来的年化报酬包含明显的波动与集中风险，不能只看 CAGR。
- **排序尚未观察到优势**：用 live 的公式（在**当日完整候选池**上取 pct-rank，不是剔除已持股后
  再算）对照同池乱序 **200 次**：score 期末权益 11.46x 落在乱序中位 11.92x **以下**、5~95 百分位
  7.44x~20.67x（第 46 百分位、单尾 p=0.547）。不能说已证明零价值，但排名不是进场理由。
- **走前选参更差**：+23.4%／0.73 对**同一窗口**冻结 5 空位 +39.7%／1.04。**这 16.3pp 是两套规则的
  样本外绩效差，不是选参偏误的规模**——walk-forward 只扫三个参数，而且用事件均值选参、
  却用组合 CAGR/Sharpe 评分（目标函数错配），两者不构成 paired optimism 比较。

全期 5 空位逐年报酬显示绩效高度依赖年份（2026 只到 7 月 24 日）：

| 年份 | 组合 | 0050 | 超额 |
| --- | ---: | ---: | ---: |
| 2020 | +65.4% | +29.8% | +35.6pp |
| 2021 | +63.3% | +21.9% | +41.4pp |
| 2022 | -13.9% | -21.4% | +7.5pp |
| 2023 | +66.5% | +27.5% | +39.0pp |
| 2024 | +13.0% | +48.6% | **-35.6pp** |
| 2025 | +20.2% | +36.9% | **-16.7pp** |
| 2026 YTD | +117.5% | +57.6% | +59.9pp |

两栏的第一年都从**原始本金**起算（不是第一列权益），所以首日进场成本落在 2020 那一格里。
2024、2025 连续落后 0050，headline 的高 CAGR 主要由 2020、2021、2023 与尚未结束的 2026 拉高；
不能只展示 2026 的右尾年份。

样本很小：125 笔（冻结）／96 笔（走前）已平仓成交、6.5 年；资料本身处在大多头（0050 全期
+408.6%）。**别外推年化。**

## 第 2 层：AI 事件面研究要做的事

量价资料看得到「涨了」，看不到「为什么涨、还能不能涨」。第 2 层要做的是分辨**催化剂可不可
延续**，具体三件事：挑出右尾（前 12% 的事件贡献总报酬 108%）、避开左尾（14.8% 的事件第 60 日
跌逾 20%）、避开主题集中（航运 34 个事件均值 +32.5%，但扣掉 2021 后 20 个只有 +1.9%、2022 起
逐年全负）。

**但要说清楚：「优势必须来自事件面研究」不是推论，是待验的假设**——第 1 层风险调整后打不赢
0050 只证明了「别拿它自动下单」，不证明事件面研究能补上那个差距，也不排除根本没有优势。

每日研究完成後，每檔候選（含 `pass`）各自 append 一行到 `journal/swing-decisions.jsonl`。
現行 row-shaped 格式不含完整候選 manifest，因此不能從日誌本身證明當天是否漏判；回驗只評估
實際留檔的決策，不把不存在或未留檔的候選補成 0。樣本不足或區間跨零時一律 inconclusive。
只有帶校準 prior 的 `breakout` 可寫正式日誌；`momentum` 僅供探索。
`confidence` 的語意鎖定為「進場後第 60 個交易日收盤淨報酬 ≥ +30%」的主觀機率，現行基準率為
**20.2%**。部位大小另看 `exp_upside`／`exp_downside`／`theme`；期望報酬是
`upside × p + downside × (1 − p)`（加号，`exp_downside` 本身为负）。

`decided_at` 必須帶時區。現行回驗保守地只取判斷日期，進場日為訊號日與判斷日期兩者較晚者的
下一交易日；出場從實際進場日起算第 60 個交易日，開盤跳空穿過 `entry_range` 上界算未成交。

## 第 4 层：怎么算这一层有没有加值

`make verify-decisions` 刻意**不看命中率**——候选池本来就是正期望值，「进场的那些赚钱」证明不了
任何事，全收也会赚。三个差值才是证据：

```
E[R|enter] − E[R|全收]        选出来的比全收好多少（<0 就是这层在扣分）
E[R|pass]                     放弃掉的后来涨了多少（机会成本）
Brier(conf) vs Brier(20.2%)   confidence 有没有比现行基准率更准
可成交口径                    同样 5 个空位下「全收 vs 只收 enter」两本帐
```

最后一项不可省：事件均值可以被同日同题材的一堆讯号撑高，真实帐户只拿得到 5 档。前三项的
差值与 Brier 都用完整交易日历的 paired circular block bootstrap；同日事件绑在一起抽样，missing
保持 missing，不补成 0。区间跨零或已到期少于 20 笔，一律标为 **inconclusive**。未满 60 个
实际持有交易日列为 pending，跳空未成交单独列出。`--entry-notional` 与 `--fee-discount` 可显式指定
回验成本；row-shaped 日誌沒有凍結成本版本，因此重跑歷史時必須沿用當時口徑，並把參數記在驗證證據中。

报酬与第 3 层逐格一致：合法进场开盘 → 实际进场后第 60 个交易日收盘 → 买卖各 0.15% 滑价、
逐笔双边手续费与卖出证交税。二代健保不是卖出费用；个人股利资料不足，故标示未扣个人补充保费。

## 验证本身的缺口（独立审查 2026-07-30 指出，尚未补）

上面的数字都能用当前程式码与当前 DB 重跑出来，但**「可重现」不等于「已验证」**。以下四项是
已知的方法论缺口，写在这里是为了下一轮不用重新发现：

1. **共模误差穿得过每一层**：同一份 `market.price_adjustment`、同一个 `load_factors`、同一组
   `tw_trade_costs` helper，同时充当实作、期望值产生器、交叉比对来源与文件来源。两支脚本的
   0050 基准现在对到小数第二位，那验证的是接线与年化一致，**不是来源正确**。
   缺的是：从未还原价 + 独立来源的公司行动（尤其 0050 在 2025-06-18 的 1:4 分割）自己算一条
   0050 财富曲线，与官方总报酬／NAV 序列对照，误差容忍度事先宣告。
2. **区间没有校准过**：`selection_lift_ci`／`paired_block_bootstrap` 只测过「完全相同两臂回
   恰好 0」「缺一臂不补零」「同日绑在一起」「seed 可重现」。缺的是注入已知 lift 验证估计量
   命中、保持 enter 笔数的置换检定验证伪阳性率接近 5%、以及自相关模拟下的 95% 区间覆盖率。
   **在那之前，回验输出的区间只能当方向参考，不能当显著性证据。**
3. **没有任何自动测试会驱动脚本打真 DB**：所有 DB 路径都是 monkeypatch 或合成面板。四支脚本
   的端到端只靠人工跑，而**「exit 0」不是正确性**——252/245 那个缺陷就是两个错的程式都 exit 0。
4. **数字没有钉住**：`docs` 只给命令，没有 pinned commit SHA、查询切片的内容哈希、机器可读的
   产出。要让这些数字可被推翻，至少要存下参数、seed、DB 切片指纹与预先宣告的容忍度。

## 站不住的部分（不要拿来当证据）

以下是早期探索量测留下的**负面 prior**（旧固定成本口径，不能与上方现行 headline 数字混用）。
它们的用途是避免下一轮重复发明已经失败的过滤条件：

- **纯技术突破没有方向性**：未来大涨约 16.4%、大跌约 16.5%，右尾与左尾几乎对称。
- **「基期平坦」不是改善**：加上平坦基期后大涨率反而降到 13.2%。
- **已经涨 20% 也没有把尾部变干净**：大涨约 18.0%、大跌约 17.4%，仍然对称。
- **简单 MA200 大盘 regime 过滤方向相反**：0050 在 MA200 下方的事件均值 +17.4%、大涨命中
  27.5%，高于 MA200 上方的 +7.3%／17.4%；不能用「跌破年线就过滤」当成已验证的降风险规则。

- **量比上限 2.0 是同样本选模**：去重后增量的 bootstrap 区间跨零，四格命中率去重后也不再单调。
  它站不住，只是还没有样本外资料可以替换。
- **上柜（TPEx）全无月营收**：`monthly_revenue` 的来源彙总报表只走 `/sii/`，所以营收条件实质上
  把池子限缩在上市。上柜的波段这条流程抓不到。
- **月营收有过存活偏误**：彙总报表只列目前仍在申报的公司。已用 MOPS 个别公司查询补回 5 档，
  82 档补不回（被吸收合并後回「不继续公开发行」）。其中 15 个价格条件事件均值 -7.23%；把
  最差 11 个作为营收条件全通过的压力情境併入，池子均值由 +9.93% 变 +9.60%（**-0.32pp**）。
  偏误真实存在，但这个可观测上界不足以翻转均值方向。
- **月营收 YoY 与命中率不单调**：20~30% 21.3%、30~50% 20.6%、50~80% 掉到 14.9%、>80% 回到 27.0%。
  「YoY 很高」本身不是理由，**它是真高还是虚高才是**。
- **创新板（-创）默认排除**：一般帐户要签风险预告书并符合资格条件才买得到。全库 25 档创新板只有
  1 档过得了 2 亿流动性门槛，而它单一笔交易就占旧版 13 年回测总损益的 85%。
- **时期依赖**：逐年只有 2022 是负的（-3.3%），但 2024 仅 +0.8%、2021 仅 +5.2%，而 2026 前七个
  月已到期事件为 +36.8%——优势集中在少数年份，别当稳定溢酬。
- **组合层的 universe 用「今天的名称後缀」判定创新板**，是 PIT 板别表还没建之前的近似；方向
  保守（排除比纳入保守），但严格来说 live、事件量测、组合回测应该共用同一个 PIT universe helper。
