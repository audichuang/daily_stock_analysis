## 3. 真正的誤判（過了對抗審查那一關的）

### 3.1 2615 萬海的 `pass`——目前為止最貴的一筆，而且錯在失效條件的寫法

- **被推翻的理由**：
  - 「跌破 MA20(79.85)」：逐日以還原收盤重算 MA20，**19 天內一次都沒跌破**——窗口最低收盤 83.60 對當日 MA20 80.74；
    08-21 收 124.50 對 MA20 91.87【覆核，方向與我實測的窗口最低收盤一致】。
  - 「法人買超中斷轉賣超」：19 天法人合計 **淨買超 +105,599 張**，只有 2 天淨賣、最長連賣 1 天【覆核】。
  - 「SCFI 連續第三週下跌」：**這一腿在寫入當天就已經成立**——SCFI 2026-07-24 報 3062.95，即第三週連跌（3080.31 − 17.36 = 3062.95，
    與日誌自己記的上週值算得起來）【覆核，外部新聞來源，本機 DB 沒有 SCFI】。之後反轉（08-07 報 3276.14），才是 08-17~08-21 那段噴出的背景。
- **所以誠實的說法不是「它靠三個後來沒發生的條件躲開」**，而是：**失效條件是 OR，其中一腿在決策時就是真的**——
  一個寫入即為真的條件不會約束任何後續行為，等於這筆 `pass` 只剩兩腿；而那兩腿量到現在都沒成立，價格卻走了 +50%。
- **哪個數字錯、錯多少**：`exp_upside = +0.42` 已被實現值超過（淨 +50.31%，還剩 41 個交易日）；
  `exp_downside = -0.16` 完全沒被測到（0 天收在成交價之下）；`confidence = 0.20` 帶出 E[R] = −0.044 才判 pass。
  但 **n=1、未到期，不能說 confidence 0.20 是校準錯誤**——只能說這一筆的 realized 已經站在 threshold（60 日 ≥+30%）的另一邊。
- **當天可知嗎**：價格方向不可知（+50% 是後段才出現的，見 4(b)）；
  **「我寫的失效條件有一腿已經成立」100% 當天可知**，這才是可歸因的流程錯誤。

### 3.2 2026-07-30 `broad_selloff` / `wait`——標籤對、動作照規則，錯在動作沒隨 flip 更新

- **標籤成立**：07-29 收盤 breadth（還原收盤 > MA20）**全體 15.12%（n=1859）、日均額 ≥1 億流動池 13.10%（n=565）**【實測】，
  對照 skill 的 broad_selloff 門檻 <25%、以及該筆記的 15.3%【日誌記載】——換哪個 universe 都過關。
- **`wait` 不是誤判**：skill 的 broad_selloff playbook 就是「不新進」，這是規則照跑，不是當天資訊集下可辨識的錯誤。
- **但代價是真的，而且要拆開講**：0050 在 07-30 開盤 93.40（決策 07:36 後第一個可執行價）→ D+1 收 +10.12%、D+5 +10.60%、到 08-21 **+12.04% 毛 / +11.28% 淨**【實測】。
  其中 **07-31 的隔夜跳空（07-30 收 93.50 → 07-31 開 100.00 = +6.95%）在 07-30 選擇 wait 之後就拿不到**；
  改成 07-31 開盤才動，到 08-21 只剩 +4.65% 毛【實測】。
- **真正的缺口是動作沒有隨自己的 flip_condition 更新**：該筆的 flip 是「費半不再跌逾 2% 且加權站回 40,000」，
  指數那一腿 07-31 開盤即成立（日誌記錄開盤 41,610.41【日誌記載】），標籤隔天也確實翻成 relief_bounce，
  但**動作五天都沒翻**：wait / wait / wait / hold / hold；07-31 那筆自己寫的 wait 理由是進場成本，不是方向。
- **日誌自己的 scorecard 把 07-30 記成「錯」，這個判定要修正**：標籤不錯、動作依規則、真正的問題是漏斗 0 檔 + 動作未隨 flip 更新。
- **這一列沒有 confidence / exp_upside / exp_downside 可以對帳**——morning-call 的欄位裡根本沒有機率欄位，這本身就是它無法算 Brier 的原因。

### 3.4 2026-08-05 `tailwind`——標籤的定義門檻自己沒過（該筆有揭露），但動作代價 ≈ 0

## 4. 少看了什麼

### (a) 當天就看得到、所以是真的流程缺口

1. **失效條件可以寫成「寫入時已經為真」而沒有人擋**（2615 的 SCFI 腿）。OR 條件裡有一腿永真＝那筆判斷的失效機制形同不存在。
2. **基準日落後一日在輪動日會給出反向結論**——日誌自己在 08-03 的 `momentum_themes` 欄寫出這句話，卻沒有套用到自己給的「法人大賣超」理由上（該理由基準日 07-31，08-03 收盤前已翻多）。
3. **漏斗第一關在跌深反彈 regime 下結構性失明，而輸出沒有揭露這件事**。實測 08-03 全體有 111 檔單日 ≥+9.5%【實測】，
   而當天噴的記憶體四檔 gate 1 全 FAIL（-21.2%~-40.4%）。報「候選 0 檔」時沒有同時報「卡在哪一關、該關的中位距離」。
4. **`breadth_ma20` 一欄裝了兩種不可比的量、且 universe 沒有任何文件定義**：盤前列是 screen_tw 的全體前一日收盤，盤中列是 ≥1 億流動池即時值【覆核】。
5. **防竄改流程破在最關鍵的那個檔案**：`journal/swing-decisions.jsonl` 只有一個 commit（`10e4b6d5`，2026-07-28 07:51，含 2615/6166 兩筆，
   在 07-28 開盤前，這兩筆是**乾淨的**）；**2408 / 3017 兩筆決策至今（決策後 10 天）仍未 commit**【實測 git】——
   而這個檔才是 `make verify-decisions` 真正讀的那一份。morning-calls 的破口見第 5 節。
6. **（小，本例未翻轉判定）`entry_range` 是原始價、`fill_ok()` 比的是還原開盤價**：3017 在 08-17 的還原開盤 3207.77 = 原始 3230 × 0.993117（08-18~08-21 之間有一次還原事件）【實測】。
   本例兩種讀法都不成交，但窗口內除息時這個口徑差可以翻轉「成交／未成交」。

### (b) 只有事後才看得到、**不是**流程缺口（不要讓它假裝是）

1. **2615 的 +50% 是後段才出現的**：到 08-14（19 天中的第 14 天）它只有 +10.35% 毛【覆核】；整段漲幅集中在最後五個交易日。
   07-27 判斷時 SCFI 還在連三跌，反轉是 08-07 才印出來的。
2. **台韓記憶體背離的收斂方向是「韓國補漲」而非「台灣回吐」**——739 個交易日 0 前例，日誌自己判 inconclusive，這個判斷是對的，n=1 不能寫成規則。
3. **「07-30 買在底部」是事後敘事**：39,933.30 確實是 `market.market_index` 的最低收盤，但那張表只有 **37 筆（2026-07-01~08-21）**【實測】；
   把窗口拉到 price 表覆蓋的 120 個交易日，07-30 在 0050 還原收盤上只排第 45 低【覆核】。當天沒有任何東西說得出它是底。
4. **韓國／美光取代費半當記憶體 proxy 的修法已經做掉了**（`scripts/kr_tw_memory_watch.py` 08-04 首日運行 22 次採樣）——**已完成，不需再列為建議**。
