## 1. 一句話現況（2026-10-24）

## 2. 什麼叫「對」

「對」的定義是：與官方**現在**的公告逐列相同。

- **代碼集合要一致**：官方有的 DB 都有，DB 沒有官方沒有的代碼。
- **每一欄數值要一致**：數字完全相等，不是近似。
- **官方回應的日期要等於請求日**：TWSE／TPEx 端點會停更新卻照樣回 200，日期不對就不算數。

比對用的官方端點與欄位：

| 資料 | 表（條件） | 官方端點 | 比對欄位 |
|---|---|---|---|
| 上市法人 | `institutional`（`market IS NULL`） | TWSE `rwd/zh/fund/T86` `ALLBUT0999` | foreign_net（外陸資，不含外資自營商；舊年份用「外資買賣超股數」）、trust_net、dealer_net（自營商合計）、total_net |
| 上櫃法人 | `institutional`（`market='tpex'`） | TPEx `insti/dailyTrade` `sect=EW` | 同上（第 4／13／22／23 欄） |
| 上市融資 | `margin`（`market IS NULL`） | TWSE `MI_MARGN` `selectType=ALL` | 資買、資賣、資餘、券買、券賣、券餘（張） |
| 上櫃融資 | `margin`（`market='tpex'`） | TPEx `margin/balance` | 同上 |
| 上市日線 | `price` | TWSE `MI_INDEX` `ALLBUT0999` | 開、高、低、收、成交股數、成交金額、成交筆數 |
| 上櫃日線 | `price` | TPEx `afterTrading/otc` `type=EW` | 同上 |
| 估值 | `valuation` | TWSE `BWIBBU_d`、TPEx `peQryDate` | 本益比、股價淨值比、殖利率（官方 `-`／`N/A` 對 DB NULL） |

**下列差異是設計，不算錯：**

- 官方收盤為 `--`（當天無成交）的列，不會入庫。
- `price.change` 不在比對範圍：程式不讀這欄，它的歷史語意見 §4。
- 盤後 18:00 抓到的當日法人是 T86 **初版**，官方事後還會修正。這由每晚 `crawl.REVISED_SOURCES` 換成定版：最近 5 個交易日（`RECENT_SESSIONS`），最多回看 31 天。報告當下即時抓的法人一律標「初版」。

## 4. 已知、接受、不修的差異

這幾項都已經查清楚，不影響任何分析：程式算漲跌一律用 `close` 自己 diff，不讀 `price.change`；唯一讀它的 `adjust.infer_rows`（推導參考價）只信 2026-08-23 之後的正負號，更早的列只用絕對值並由漲跌停帶證明方向。

|---|---|---|
| 上市 `price.change` 沒有正負號 | 2010～2012 | 那段沒有復權因子，硬補會讓除權息日方向錯；`backfill_price_change_sign.py` 刻意從 2013 起 |
| 上市 `price.change` 把官方 `X`（無比價）存成 0 | 2026-08-23 以前抓的列，每天約 4～30 列 | 舊爬蟲語意；新爬蟲已存 NULL |

## 6. 正式應用庫（`dsa` schema）的判準

- **匯率**（`portfolio_fx_rates`）：
  - 每天一列，`source` 標明來源：`yfinance`（當日刷新）、`yfinance_backfill`（倫敦日最後一根 1h 收盤）、`yfinance_cross`（垃圾值被拒收後以 USD 兩腿交叉換算）、`manual`。
  - `is_stale=true` 表示那天沒有可信收盤、沿用前值。持倉頁遇到 stale 就隱藏回撤、集中度、曝險等卡片，所以**卡片「不可用」先查這張表**。
  - 週末不會有新收盤，沿用週五值且不標 stale。
- **測試不可寫進正式庫**：`tests/conftest.py` 會往上層找 `.env`，在 worktree 裡也擋得住。10-23 那次漏寫，推測是有人在 `tests/` 以外跑了臨時測試檔，根因未完全重現。**臨時腳本一律把 `STORAGE_DATABASE_URL` 設成空字串。**

## 7. 怎麼驗證（runbook）

### 逐日比對官方

```bash
# 例：最近兩個月、全部來源（TWSE／TPEx 各一條執行緒，每請求間隔 4 秒；60 天約 15 分鐘）
uv run --env-file .env python scripts/audit_market_vs_official.py \
    --start 2026-09-01 --end 2026-10-23 --out data/audit/2026-10 \
    --sources t86,margin,price,tpex_insti,tpex_margin,tpex_price
# 只看彙總（不連網）；有差異或讀不到的日子時結束碼 1
uv run --env-file .env python scripts/audit_market_vs_official.py --out data/audit/2026-10 --summary
```

`result.jsonl` 每天每個來源一行，欄位意思如下：

- `miss`：官方有、DB 沒有。
- `extra`：DB 有、官方沒有。
- `bad`：兩邊都有但數值不同的列數。`ex` 附前幾個例子，列出代碼和不同的欄位序號。
- `err`：官方回應日期不符，或表頭認不得。這**不是資料錯**，要人工看原始回應 `raw/`。

**看到差異時怎麼判斷：**

1. 先用官方原始回應（`raw/`）和 `psql` 抽一兩檔核對，排除比對工具本身的錯。
2. 再看差異形狀：
   - 只差投信，或缺幾檔 K 結尾的外幣 ETF：T86 初版。
   - 整欄是 0 或 NULL：抓取時欄位缺漏。
   - 整天的值等於另一天：錯置。
   - 量、額、筆偏少但開高低收正確：抓得太早，盤後交易還沒併入。
3. 以上都要整日重抓。

**不要**同時跑兩個打 TWSE 的工作，例如比對加回補，否則會被 WAF 擋下。失敗時有些會靜默跳過。

### 整日重抓（寫正式庫）

```bash
uv run --env-file .env python -m market_data.cli backfill institutional --start 2026-07-28 --end 2026-07-28 --force
```

- 一天一次呼叫，間隔 4 秒以上。
- `--force` 會整日替換，只刪該市場的列（上市法人不會刪到上櫃）。新資料筆數不到舊資料一半，或欄位品質變差時，會拒收並印 `**WARN`。
- 寫法照 `.claude/backups/20261024/run5.sh` 的格式：
  1. 先 `\copy` 備份。
  2. 遇到 `WARN`、`refused`，或寫入 0 列就停。
  3. 結束後重跑比對，必須 0 差異。
- 在 Claude Code 裡，寫正式庫會被自動模式擋下：把腳本寫好交給使用者執行（`! bash <相對路徑>`）。

## 8. 例行維運建議

- **每月一次**：用 §7 的指令比對最近 60 天的全部來源，`--summary` 結束碼要是 0。超過 `REVISED_SOURCES` 最多回看 31 天的窗，抓得到窗外凍結的初版。
- **改爬蟲、ETL 或 `crawl.py` 之後**：至少比對受影響來源最近 30 天，再加上任意 5 個歷史日。
- **每晚日誌要看的訊號**：
  - `**REVISED`：官方事後修正了已入庫的值，屬於預期，T86 隔天常見。
  - `**WARN … refused`：重抓被拒收，需要人工看。
  - `cannot parse … header not found`：端點格式改了或被擋。
- **price 不在 `REVISED_SOURCES`**：2026-07～09 的量能缺口就是這樣凍結的。09-30 起逐日一致（推測與抓取排程改到 18:00 有關，未證實）；之後若又看到「量偏少但價對」，要考慮把 price 加進去。
