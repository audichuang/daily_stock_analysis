# 點名來源擴充：財經頻道篩選與 PTT 標的文（2026-10-23）

研究紀錄，當天快照。現行規則的正本是 `scripts/tw_media_picks.py` 的 `CHANNELS`、`scripts/tw_ptt_picks.py` 與 `journal/README.md` 的欄位說明；這份記錄**為什麼收這些、不收那些**，以及試跑時抓到的問題，避免下次重查。

**定位不變：媒體點名與 PTT 標的文都是候選來源，不是買進訊號。** 來源是節目來賓、投顧（頻道在招攬會員，有利益衝突）與匿名網友；點名的事後表現目前是 inconclusive（`docs/research/2026-10-22-tw-media-sweep.md`），這份沒有任何報酬或命中率的結論。

## 1. YouTube 頻道：從 21 個擴到 25 個

候選來源：MoneyForecast 的中文財經 YouTuber 目錄（666 個頻道）、網路搜尋，實際用 yt-dlp 探測約 20 個頻道。收錄條件：

- 有固定的**完整版**集數（片段、精華會重複計數），標題或片長能篩得出來。
- 每天或每週數次更新，內容會**具體點名台股**。
- 公開影片（會員專屬抓不到）。
- **上傳時刻在當天資料公開之後**，或標題寫得出「盤前」。這條最容易漏，見 §3。

## 2. PTT 股票板 `[標的]` 文

`[標的]` 是板規格式的推薦文，作者要寫標的、分類（多／空／討論）、分析與進退場機制，所以**直接解析原文、不經 LLM**；`Re:` 回文沒有固定格式，不收。股名轉代號沿用 media-picks 的 `resolve`。

試跑 10-12～10-23：22 篇，約一週 12 篇。

| 項目 | 篇數 |
| --- | --- |
| 對到個股代號 | 14（股名 9、代號 4、字面相近 1） |
| 大盤、台指期、美股 ETF（`market`） | 5 |
| 對不到／代號與股名不合 | 2／1 |
| 看多／中性 | 14／8（沒有看空） |
| 有寫進退場機制 | 18 |
| 發文後編輯過 | 8 |
| 附對帳單 | 1 |

一篇寫兩檔（例如「0052、2330」）只記第一檔。推噓數是擷取當下的值，文章越新越少。

## 3. 審查抓到的問題（review-gate 三輪＋一輪小改）

Codex 與 Opus 第 1 輪獨立審，Codex 第 2、3 輪只審修正。下面每一條都已重現、修正，並有修前會失敗的測試。

**資料截止日（look-ahead）**：`data` 附的是發文或播出當時「已知」的資料，有三個洞：

- `data_cutoff` 原本只看標題有沒有「盤前」。理周TV 有上午 10 點上傳的盤中連線，標題沒寫盤前，會拿到當天收盤。
- 13:30 收盤後就用當天資料，但個股的三大法人買賣超下午才公布。
- yt-dlp 的 `upload_date` 是 **UTC 日期**：台北早上 8 點前上傳的會被算成前一天。另外 yt-dlp 有時只給日期、不給時間戳。

現行規則：用台北時間的上傳時刻（或 PTT 的發文時刻）判斷，當天 17:00（`DATA_KNOWN`）以前的只用前一天的資料；沒有時間戳時，以 UTC 上傳日的開始（台北 08:00）當最早可能的時刻。2026-10-23 晚上以前寫入的 media-picks 列只看標題，下午上傳的集數可能含當天法人。

**代號對錯**：

- 板規範本的「(例 2330.TW 台積電)」沒刪掉時會被當成標的；但只能刪「例」後接數字的範例，否則會連「（例外：跌破 900 停損）」這種正文一起刪掉。
- 作者寫的四位數不一定是台股代號（小米 1810、年份 2025），所以先比對股名，數字跟股名不合就標成 `code_mismatch`。
- 「台灣大盤」的字面相近比對會對到台灣大（3045），所以大盤字眼不做字面相近比對。

**無人值守的失敗模式**：

- 維護頁或擋爬頁回 HTTP 200 時，原本會被寫成一篇文章，之後永遠不再重抓。
- 搜尋結果某一頁剛好全是回文時，原本會提早停止翻頁。
- 搜尋頁一篇都沒有時，原本照常結束、不會報錯。
- 股價數據抓取失敗時，原本會寫成 `data=null`、不再重試。

現行行為：前兩種改成翻頁與停止都看所有結果；搜尋頁抓不到或第一頁就 404 會讓程式失敗結束；文章頁不對或抓股價數據失敗的那篇不寫，下一輪重抓。

**內容會被改**：`[標的]` 文常在發文後編輯，擷取讀的是當下的內文。現在記下 `edited_at`，回驗時應排除編輯過的文，或改用編輯時刻當基準。
