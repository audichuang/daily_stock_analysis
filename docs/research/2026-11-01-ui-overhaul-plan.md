# UI 全面改版計畫

2026-11-01 定稿。共 91 張票、14 批，一批一個 PR。來源是 28 份頁面審查、88 張初版票與 40 條對照 repo 的修正；票的完整內容（範圍、檔案、依賴、驗收）在 `docs/research/2026-11-01-ui-overhaul-tickets.json`，這份只看全貌與進度。

## 目標

- 打開就看得到結論：報告首屏先給動作、一句話與價位，持股與空手分開講。
- Web 與 iOS 用同一套詞彙和語意色，繁中介面不再混簡體與機器值。
- 手機可以直接用：不靠橫捲，分頁列不蓋內容。
- 數字不互相打架：今日損益、總資產、現價各只有一個來源。
- 每張版面票都在真實畫面上驗過，不只跑單測。

## 已定決策

| 項目 | 決定 |
|---|---|
| iOS 登入 | 密碼登入維持現狀，Cloudflare Access service token 由 PR #166 處理。不做密碼自動填入與 AASA |
| 首頁落點 | 留在 `/`。未選股顯示今日總覽，選股後才顯示報告，不再自動開最新一份 |
| 深連結 | 現況 `/` 沒有 URL 參數，只有 `location.state` 與清單選取，這些入口都要保留 |
| iOS 主色 | 維持現色，不開改色票 |
| iOS 原生警報與問股 | 移出本次改版，工具頁繼續走內嵌 |
| 動作顯示 | 報告、清單、版本比較都依 `action` 枚舉對應詞彙表，不讀存檔的標籤。舊報告存「減倉」，畫面一律顯示「減碼」 |
| 用語 | 警報、持股（導覽叫資產）、買進、賣出、減碼、加碼、續抱、觀望；正本是 G01 的 `docs/glossary-zh-tw.md` |
| 顏色 | 紅綠只給行情方向與損益（紅漲綠跌）；動作用品牌色、灰、琥珀 |
| API | 一律追加，舊欄位不動。B 票只動後端，型別與 fixture 由使用它的票負責 |
| 部署 | 每批合併後直接發 NAS 與內部 TestFlight，已授權 |
| 全量測試 | 每批合併前跑全量離線測試，已授權 |

## 每批都要做到

- 分支用 `feat/` 前綴才有 CI；CI 綠才合進 `develop`。
- 合併前跑 `uv run ./scripts/ci_gate.sh`。跑全量期間不改檔，也不和 vitest 全量並行。
- 版面票用 verify skill 實測：Web 預設 1440×900 與 390×844，iOS 用 DSA iPhone 18 Pro Max，判準寫在各票 `verify`。
- 新增 Swift 檔要跑 xcodegen 並提交 `project.pbxproj`。
- 使用者可見變更寫進 `docs/CHANGELOG.md` 的 `[Unreleased]`；新設定同步 `.env.example`，不設也要能跑。這三處（含 `config_registry.py`）只是追加，不算票間依賴，rebase 解決。
- 守修法的測試要做正反 mutation。
- 部署後登入正式站點過一輪、截桌機與手機圖；TestFlight 要讀回 VALID 與群組。

## 順序上的限制

1. **PR #166 先合併。** 它還開著，且和 I01a、W01b、I15、I16、`fixture-server.py`、`test-ui.sh` 共用檔案。第 1 批要等它進 `develop`。
2. **內嵌先於底部分頁。** W01a、W01b 在第 2 批，N02 在第 11 批。N02 部署前，W01b 那版要已在 TestFlight 且手機已更新，否則舊 App 的內嵌頁會多一條底部分頁。
3. **B01 自帶語言表。** B01 一部署，舊版 iOS 就會顯示報告的失效條件，所以英文模板的修正併進 B01，不等 B03。
4. **標籤改名在別名之後。** B04 改成「減碼、買進」，要等第 1 批的 D01、I01a 認得新詞。
5. **警報 UI 的完成條件是 NAS 監控在跑。** 見 L03。
